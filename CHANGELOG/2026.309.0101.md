# 2026.309.0101 — feat(image): add the browser lease image pod-crabbox-browser

## Summary

Adds `pod-crabbox-browser`: the browser lease image for the Crabbox `containerd` provider, one of the `pod-crabbox-<variant>` images tracked by opencharly/opencharly#869 (W5.2). It is the base lease contract (`opencharly/pod-crabbox`, pinned) plus Chromium and Firefox and a launcher that keeps the Chromium sandbox enabled.

- **`charly.yml`** — the image: `base: ghcr.io/opencharly/pod-crabbox:2026.307.1828` (pinned OCI base), `user: root` (the base's `sshd -D` is PID 1) with the login user left at the base's `crabbox`/uid 1000, and `distro: [cachyos, arch]` + `build: [pac]` declared explicitly because an external OCI base does not inherit the CachyOS chain.
- **`candy/crabbox-browser/charly.yml`** — the variant layer: Chromium and Firefox from the Arch repo package set (`distro.arch.package`), the launcher copied to `/usr/local/bin/crabbox-browser` mode `0755`, and the base's SSH port (`2222`) restated because an OCI base does not carry its candy chain's port label across the boundary.
- **`candy/crabbox-browser/crabbox-browser`** — the launcher: `exec chromium --no-first-run --no-default-browser-check --user-data-dir="${HOME}/.config/crabbox-chromium" "$@"`. It never passes `--no-sandbox` or `--disable-setuid-sandbox`: on crun/runc the host runs the lease with the narrow `/etc/containerd/seccomp/crabbox-userns.json` profile, and under krun the guest kernel is the boundary.
- **Six deterministic `check:` steps** — `chromium --version` contains `Chromium`; `/usr/bin/firefox` is executable; the wrapper is executable and, ignoring comment lines, contains neither `--no-sandbox` nor `--disable-setuid-sandbox`; the inherited lease binaries (`sshd`, `bootstrap.sh`, `ready`) exist; uid 1000 is `crabbox`; `/etc/ssh/sshd_config.d/99-crabbox.conf` names `Port 2222` and `sshd -t` parses it.
- **`.github/workflows/image.yml`** — the thin caller of the org reusable: `pull_request` / `workflow_dispatch` build only (the reusable derives a `ci-<sha>` tag and publishes nothing), and a successful `tag-on-merge` completion publishes the newest `v*` git tag as the image tag.
- **`README.md`, `AGENTS.md`, `CHANGELOG/.gitkeep`, `.gitignore`** — repo overview, repo guidance, the history directory, and generated-file ignores.
